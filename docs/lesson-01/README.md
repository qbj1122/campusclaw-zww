# 第 1 课验收记录

## 本课任务

1. 理解课程三条主线：产品（CampusClaw）、方法（SDD）、工具（Harness）。
2. 理解互联网应用必须同时满足功能、性能、安全；能运行不等于可上线。
3. 理解 LLM、智能体、知识库/RAG、技能、MCP 五个概念在产品中的位置。
4. 课后小练习：用氛围编程（不先写规约）完成一个可运行的小项目并放入 Git 仓库。

## 本仓交付

- `prototype/lesson01-timetable/index.html`：单文件班级课程表，支持添加课程、按星期筛选、节次冲突拒绝保存；数据存 `localStorage`，不接真实用户数据与密钥。
- 本记录：对氛围编程过程的复盘，以及它与后续 SDD 交付的对照。

## 运行

直接用浏览器打开 `prototype/lesson01-timetable/index.html`，或在仓库根执行：

```bash
python3 -m http.server 8001
# 打开 http://127.0.0.1:8001/prototype/lesson01-timetable/
```

## 复盘：氛围编程快在哪里、丢在哪里

| 观察 | 本次练习中的表现 | 对后续课程的约束 |
|---|---|---|
| 单步反馈快 | 一句描述即可得到可操作的页面 | 适合探索交互与确认需求 |
| 决策留在对话里 | 为什么用 `localStorage`、冲突判定放在前端，最初没有写下来 | 第 2 课起把“谁、做什么、不做、失败时怎样、证据”写进 OpenSpec |
| 失败路径靠临时补 | 节次冲突是演示中才追加的 | 第 3 课起先写跨班、未登录、学生上传等失败 Scenario |
| 只对当次预览负责 | 刷新能看见数据，但没有权限、隔离与审计 | 第 3–6 课用服务端强制、审计与接口测试判定完成 |
| 换人或换模型难复现 | 没有统一命名与错误结构 | 第 7 课前的工程规范把约定写进 `AGENTS.md` 与技能 |

## 与最终系统对照

| 第 1 课概念 | 最终仓库中的落点 |
|---|---|
| 互联网应用：登录、角色、数据归属 | Bearer JWT + 服务端角色判定 + 班级隔离 |
| 功能、性能、安全 | `/health`、SSE 首字延迟、跨班 404、密钥只在服务端 |
| LLM | 服务端调用 OpenAI 兼容网关，流式输出；无密钥时离线回退 |
| 智能体 | `agents` + 提示词 + 技能/材料绑定 + 会话锁定 |
| 知识库/RAG | MySQL 切片正文 + Qdrant 向量 + 混合检索 + 引用 |
| 技能 | 单文件技能、确定性路由、可启停 |
| MCP | 自建 `mcp-server/`、连接发现、工具调用、审计 |

结论：第 1 课的练习证明了“生成很快”，但没有证明“谁能看、失败时怎样、换一个模型能否复现”。这三件事从第 2 课起由规约、服务端约束与证据补齐。
