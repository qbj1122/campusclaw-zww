# 第 1–6 课任务对照与实现说明

> 阅读顺序：先读完整链路，再逐课实现。后面课程会修正前面课程的临时选择；本仓库以最终形态为准，并在各课记录中注明冲突处理。

## 第 1 课：做成可上线、可验收的互联网应用

**课堂任务**

- 建立三条主线：产品（CampusClaw）、方法（SDD）、工具（Harness）。
- 理解互联网应用的功能、性能、安全三重约束；能运行不等于可上线。
- 理解 LLM、智能体、知识库/RAG、技能、MCP 五项能力在产品中的位置。
- 课后：用氛围编程完成一个小项目，放入 Git 仓库，提交仓库地址。

**本仓实现**

- `prototype/lesson01-timetable/index.html`：课程表小练习，支持添加、按星期筛选、节次冲突拒绝。
- `docs/lesson-01/README.md`：对“快但决策流失”的复盘。
- 第 1 课的五项能力在后续课程全部落入主业务，而不是独立聊天页。

**证据**

- 直接打开原型可操作；冲突时段不会写入。
- 复盘表逐项对应后续的服务端鉴权、班级隔离、检索引用、技能开关与 MCP 审计。

## 第 2 课：SDD 与 CampusClaw 规约

**课堂任务**

- 新建学期仓，写 README 三行说明与“无规约不写代码”的规则文件。
- `openspec init --tools <Harness>`，用 `/opsx-propose` 起草第一个变更。
- 四件套齐全：`proposal.md`、`design.md`、`specs/<能力>/spec.md`、`tasks.md`。
- 覆盖登录、角色权限、班级隔离、教师上传入库；明确 Non-goals；Scenario 可判定。
- 当堂不写业务代码，checkbox 保持未勾选；`openspec validate --strict` 通过。

**本仓实现**

- `openspec/changes/archive/*-add-auth-rbac-class-knowledge/`：第 2 课变更的完整四件套与归档。
- `openspec/specs/auth-upload/spec.md`：归档后的长期能力规约。
- `AGENTS.md`、`README.md`、`openspec/config.yaml`：仓库规则与上下文。

**证据**

- `openspec validate --specs --strict` 通过；每条能力至少一组 Scenario，失败路径覆盖未登录、学生上传、跨班访问、密钥缺失等。
- 归档目录保留“当时为什么这样做”的 design 与 tasks。

## 第 3 课：认证授权与知识库入库

**课堂任务**

- 用 Go + MySQL 实现骨架、登录、角色权限、班级隔离、教师上传入库。
- 服务端会话/令牌、bcrypt 密码哈希、密钥只从环境变量读取。
- Docker Compose 启动，`GET /health` 免认证；数据库与上传目录持久化。
- 跨班与不存在一致返回 404；学生上传 403；前端隐藏按钮不算权限。
- 按 tasks 实现、校验、归档，留下验收证据。

**本仓实现**

- `cmd/server/` + `internal/{config,db,auth,store,httpapi}`；MySQL 8；`docker-compose.yml`。
- JWT Bearer 登录（第 5 课迭代，覆盖第 3 课的 Cookie 临时方案），角色与班级每次回库读取。
- 教师上传 `.txt/.md` → 原文落盘 + `materials` + `knowledge_entries.body_text` 同事务；失败回滚并删文件。
- 种子：班级 A/B、教师/学生账号、两班可区分材料、技能与助手。
- `/health` 只做存活判定，不查数据库。

**证据**

- `apitest/cases/api/login/POST.py`、`materials/POST.py`、`materials/{id}/GET.py` 等。
- `docs/lesson-03/README.md` 记录请求/响应、数据库核对与失败路径。
- `docker compose config` 通过；Compose 只暴露 `web` 端口。

## 第 4 课：可追溯知识库检索

**课堂任务**

- 同一系统增量实现：正文切片、向量入库、`keyword/vector/hybrid` 三种检索、引用标注、无依据拒答与不调用模型。
- 切片正文存 MySQL，向量存 Qdrant；向量主键等于切片主键。
- 班级仅取自会话；关键字与向量两条路径都过滤；跨班检索表现为无命中，不返回 403。
- 切分策略 `auto`（约 800 字、重叠 80）、`custom`（100–2000 字、重叠 0–50%）、`hierarchy`（按标题分章）。
- 改策略须重建索引；嵌入失败保留材料、切片标记 failed。

**本仓实现**

- `internal/chunk`：三种策略与偏移量。
- `internal/store/retrieval.go`：`knowledge_chunks`、FULLTEXT ngram、索引状态、回表。
- `internal/vector`：Qdrant REST 客户端；collection `campusclaw_chunks`，余弦。
- `internal/service/retrieval.go`：RRF k=60、向量阈值 0.35、分页、跨班过滤。
- `POST /api/search` 与 `POST /api/ask`；`GET /api/materials/{id}/vectors` 只展示切片元数据。
- `POST /api/materials/{id}/reindex` 先删旧切片与旧向量，再按本次策略重建。

**证据**

- `docs/lesson-04/README.md`：三种模式的命中差异、跨班空结果、无依据固定文案。
- `apitest/cases/api/search/POST.py`、`ask/POST.py`。

## 第 5 课：提示词、AI 技能与流式会话

**课堂任务**

- 教师设置提示词，维护至少一条“解题引导”技能（只引导、不直接给最终答案）。
- 学生新建会话、提问后流式看到回答；回答前先检索本班知识库，引用可见。
- 智能体绑定技能与材料；会话锁定智能体；技能可启停、按适用条件路由。
- SSE 事件：`meta`（技能/引用）先到，`delta` 增量，`done` 收尾。
- Bearer 令牌访问；Swagger 可打开并试调；apitest 一键跑并生成 HTML 报告。

**本仓实现**

- `agents`、`agent_skills`、`agent_materials`、`conversations`、`messages` 表。
- 技能单文件解析：元数据 + 空行 + 正文；工具只允许 `knowledge_search`（第 6 课扩展 `tool@server`）。
- 确定性词法路由，至多一个技能，同分取编号小者；停用/解绑下一次提问立即生效。
- 系统消息只放提示词、技能说明与边界句；资料编号放用户消息；最近 6 条历史、每条 500 字。
- `POST /api/conversations/{id}/messages/stream` SSE；Nginx 关闭缓冲，服务端每帧 flush。
- `/api/ask` 保持第 4 课口径（无依据不调用模型）；流式路径无依据仍作答、引用为空、剥掉 `[n]`。

**证据**

- `docs/lesson-05/README.md`：流式抓包、引用顺序、技能停用前后对比、跨班 404。
- `apitest/cases/api/conversations/{id}/messages/stream/POST.py`。
- `/swagger/` 与 `/openapi.json`。

## 第 6 课：MCP 与工具接入

**课堂任务**

- 同仓新增 `mcp-server/`：`POST /mcp` JSON-RPC 2.0，`initialize`、`tools/list`、`tools/call`，`/health`，Bearer 鉴权，至少两个工具。
- 教师登记服务器（名称、Base URL、令牌）；令牌只在服务端，响应只回 `has_auth`。
- 连接 = 握手 + 发现；失败停未连接；成功整体替换工具缓存；断开清空；重复连接不翻倍。
- 技能“工具”栏支持 `工具名@服务器名`；保存前校验格式、服务器存在、已连接、工具在清单内。
- 学生提问命中技能时按白名单调用；工具返回先过安全检查，作为数据进入用户消息；`meta.tool_calls` 先于正文。
- 每次调用写审计：`tool_ref`、状态（ok/denied/error）、用户、会话、时间；三种状态可见；服务器改名/删除时不写审计。
- Swagger 补齐 MCP 接口；apitest 增加管理与端到端用例。

**本仓实现**

- `cmd/mcp-server/`：`formula_hint`、`unit_convert`，令牌比较使用常量时间，JSON-RPC 错误码完整。
- `mcp_servers`、`mcp_tools`、`mcp_tool_calls` 三张表；连接覆盖缓存，删除有审计的服务器返回 503。
- 技能引用解析与四道保存校验；调用顺序固定在推 `meta` 之前；单次提问工具调用上限 `MAX_TOOL_CALLS_PER_REQUEST`（默认 8）。
- 工具输出命中“忽略前述 / system: / 请调用 / 外发地址”等句式或超过 1200 字时整条丢弃，替换为固定说明。
- 管理接口全部仅教师；学生 403；跨班服务器按不存在处理。

**证据**

- `docs/lesson-06/README.md`：`/health`、带令牌 `tools/list`、连接/发现/绑定/调用/审计、断开后 denied、令牌不回传、上限生效。
- `apitest/cases/api/mcp/...` 与端到端用例。
- 同伴交叉验证清单已留在记录中，需由同伴以自己的账号在同一套环境复核并附截图/日志。

## 冲突处理记录

| 冲突 | 处理 |
|---|---|
| 第 3 课要求 Cookie+Session 且明确不用 JWT；第 5 课迭代为 Bearer JWT | 以后面的课为准，最终实现 Bearer JWT；角色与班级仍回库读取，登出写吊销表 |
| 第 2 课示例用 Flask/SQLite；第 3 课起明确 Go + MySQL | 采用 Go + MySQL 8 + Qdrant + Nginx + Compose |
| 第 2 课跨班可 403 或 404；第 3 课要求与不存在一致 | 统一 404 |
| 第 4 课“无依据不调用模型”；第 5 课流式路径“落空仍作答” | 两条接口并存，各自保留口径；流式无引用且剥掉编号 |
| 第 6 课任务清单写“模型提出调用”；第 6 课实现教程写“先调工具、再生成，模型不持有开关” | 采用同一课更详细的实现教程：确定性编排，技能白名单 + 单轮调用上限 + 审计；在 `docs/lesson-06` 说明取舍 |
